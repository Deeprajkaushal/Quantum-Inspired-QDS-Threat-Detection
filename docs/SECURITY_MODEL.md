# Security Model & Threat Specification

## 1. Asset Classification
- **Message Authenticity:** Guaranteeing that the payload was generated by the legitimate sender.
- **Signature Non-Repudiation:** Ensuring sender cannot deny signature generation.
- **Freshness & Replay Prevention:** Preventing reuse of previously intercepted signatures.
- **Verifier Authorization:** Restricting verification capability to authorized entities.

## 2. Threat Vector Matrix

| Attack Mode | Threat Description | Detection Indicator | Mitigation Strategy |
|---|---|---|---|
| **Forgery** | Tampering with message or quantum state payload | Error rate > Threshold, SHA-256 mismatch | Reject signature, flag forgery |
| **Impersonation** | Unauthorized sender attempting signature | Key/state discrepancy, invalid digest | Reject signature, audit sender ID |
| **Replay Attack** | Resubmitting previously accepted signature | Reused nonce in session ledger | In-memory ledger rejection |
| **Channel Noise** | Quantum channel phase/bit flips | Elevated error rate above noise margin | Flag channel disturbance |
| **Unauthorized Verification** | Unauthorized verifier request | Verifier ID not in ACL | Reject verification immediately |

## 3. False Positives vs False Negatives
- **False Positive (Legitimate rejected):** Occurs if channel noise parameter exceeds acceptance threshold.
- **False Negative (Threat accepted):** Occurs if threshold is set excessively high (e.g. > 0.45).
